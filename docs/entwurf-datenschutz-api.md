## Sprachmodell (entschieden am 27.10.2026)

OpenAI schaltet `gpt-5-nano`, den bisherigen Standard für den Fallback, und `gpt-5-nano-2025-08-07` am 11.12.2026 ab und nennt `gpt-5.6-luna` als Nachfolger (Abkündigungsseite, Abschnitt „2026-06-11: GPT-5 and o3 model deprecations“, abgerufen am 27.10.2026). Mit dem alten Standard scheiterte danach jeder Aufruf mit mindestens einem unsicheren Händlernamen insgesamt mit 502, weil der Fallback ohne eigene Fehlerbehandlung läuft (`apps/web/lib/kontoklar/server.ts`).

Der Autor hat am 27.10.2026 `gpt-5.6-luna` gewählt. Seitdem ist es der Standard: `DEFAULT_FALLBACK_MODEL` in `apps/web/lib/kontoklar/types.ts` (von `providers.ts` verwendet), `apps/web/.env.example`, README und `docs/einrichtung-api.md`; `apps/web/lib/kontoklar/__tests__/providers.test.ts` prüft, dass Code, `.env.example` und die Variablentabelle im README übereinstimmen und dass der Aufruf nur Modell, JSON-Modus und Nachrichten enthält. Die Modellseite nennt den Anzeigenamen „GPT-5.6 Luna“, die Preisseite nur die ID; der Text nennt die Modell-ID, weil sie aus `DEFAULT_FALLBACK_MODEL` kommt und so nicht vom Code abweichen kann.

Offen ist ein echter Aufruf: Ob `gpt-5.6-luna` den JSON-Modus annimmt, den der Code verwendet (`response_format: { type: "json_object" }`), lässt sich der Modellseite nicht sicher entnehmen; sie nennt Chat Completions und Structured Outputs, aber keinen JSON-Modus. Geprüft wird das mit dem ersten `pnpm --filter web accuracy --api` (Prüfliste, Punkt 2): Das Skript meldet, wie viele Texte an das Sprachmodell gingen und wie viele es zugeordnet hat, und bricht ab, wenn es keinen zuordnet. Scheitert der Lauf mit Fehler 400 oder bricht er so ab, den Code auf Structured Outputs (`json_schema`) umstellen. Bei der Übernahme den Modellnamen nicht von Hand in `page.tsx` schreiben, sondern `DEFAULT_FALLBACK_MODEL` aus `types.ts` als `fallbackModel` in `PRIVACY_FACTS` übernehmen (dort liegen schon die anderen Werte wie `CACHE_TTL_SECONDS`) und in `privacy.test.ts` prüfen; dann können Seite und Code nicht auseinanderlaufen. `KONTOKLAR_FALLBACK_MODEL` in Vercel darf nur gesetzt werden, wenn der Wert zum veröffentlichten Text passt.

## Zu entscheiden und zu prüfen (Hinweise, keine Rechtsberatung)

Offen ist nur der echte Aufruf zum JSON-Modus (siehe „Sprachmodell“).
2. **Rechtsgrundlage von Turnstile und § 25 TDDDG.** Turnstile liest Informationen aus dem Browser aus. Das ist ohne gesonderte Einwilligung zulässig, wenn es unbedingt erforderlich ist, um einen vom Nutzer ausdrücklich gewünschten Dienst bereitzustellen (§ 25 Abs. 2 Nr. 2 TDDDG). Turnstile lädt erst nach dem Haken für den API-Schritt, der seinerseits auf Einwilligung beruht (lit. a); die geltende Erklärung stützt die Bot-Prüfung bisher auf lit. f. Optionen (Wortlaut im Platzhalter): (a) lit. f mit § 25 Abs. 2 Nr. 2 TDDDG, Cloudflare Turnstile im Hinweis beim Anhaken ausdrücklich nennen (das tut der Hinweis bereits); (b) die Bot-Prüfung in die Einwilligung nach lit. a einbeziehen. Das Ergebnis von Prüfliste Punkt 7 fließt ein. Rechtliche Bewertung, ggf. mit fachkundiger Stelle.
3. **Eigene Zwecke der Anbieter.** Cloudflare nutzt die Signale nach eigenen Angaben auch als Verantwortlicher zur Verbesserung von Turnstile (berechtigte Interessen); der Entwurf nennt das. Upstash nimmt nach der Präambel seines DPA eigene Zwecke von diesem aus: Kundenverwaltung, Marketing und Service-Analytics, Sicherheit der eigenen Systeme sowie rechtliche Pflichten. Davon zu trennen ist Annex 1 des DPA: Danach darf Upstash die gespeicherten Daten im Auftrag auch zur Verbesserung seiner Dienste verarbeiten; das steht bereits im Upstash-Absatz. Optionen: (a) den Satz zu den eigenen Zwecken von Upstash übernehmen (Platzhalter „EIGENE ZWECKE“); (b) weglassen. Empfehlung: (a) aus Gründen der Einheitlichkeit mit Cloudflare.
4. **Speicherdauer bei Cloudflare.** Cloudflare nennt für Turnstile keine Frist. Ob „gibt Cloudflare nicht konkret an“ für Art. 13 Abs. 2 lit. a DSGVO genügt, ist rechtlich zu bewerten.
5. **Datenresidenz bei OpenAI.** Der Code übergibt weder `baseURL` noch `dataResidency`, das OpenAI-SDK (7.38.0) nutzt deshalb `https://api.openai.com/v1` oder, falls gesetzt, die Umgebungsvariable `OPENAI_BASE_URL`. Die Option `dataResidency` (global, us, eu, ae) wählt einen regionalen Endpunkt nur, wenn sie im Code übergeben wird; eine Umgebungsvariable dafür liest das SDK nicht (geprüft in `openai/internal/data-residency.js` und `openai/client.js`). Der Entwurf geht von einer möglichen Verarbeitung in den USA aus. Eine Verarbeitung in Europa (`eu.api.openai.com`, ohne Codeänderung über `OPENAI_BASE_URL`) setzt laut OpenAI eine Freigabe für Zero Data Retention, Modified Abuse Monitoring, Private Retention mit PSP oder Safety Retention und ein unterzeichnetes Modified Retention Amendment voraus; für Modelle ab dem 05.03.2026 kommt ein Preisaufschlag von 10 % hinzu. Empfehlung: bei `api.openai.com` bleiben und `OPENAI_BASE_URL` in Vercel nicht setzen, weil eine gesetzte Variable den Endpunkt unbemerkt umstellen würde (alternativ `baseURL` im Code fest setzen).
